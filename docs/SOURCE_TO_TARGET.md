# Parcel warehouse — source-to-target mappings

**Status:** Step 4 full mapping design; Silver mappings through physical attempts, certificates, summaries and calendar are implemented and tested in Steps 6A–6C. Gold mappings are implemented and tested in Step 7. Object definitions are in [WAREHOUSE_DESIGN.md](WAREHOUSE_DESIGN.md). This document maps **all 49 contracted fields**; it adds no source field or business rule. Short references: **SC** = [SOURCE_CONTRACTS.md](SOURCE_CONTRACTS.md), **ER** = [EVENT_AND_CUTOFF_RULES.md](EVENT_AND_CUTOFF_RULES.md), **DP** = [DATA_GENERATION_PLAN.md](DATA_GENERATION_PLAN.md), **PS** = [PROJECT_SPEC.md](PROJECT_SPEC.md). `F01`–`F14` and variant names refer to DP's known-answer fixtures. These are test references, never pipeline input values.

## Shared field and provenance mapping

For each parseable CSV record, place **every parsed field string unchanged** in the identically named `bronze.<source>` column. Preserve empty fields as `N''`, not SQL NULL, until type interpretation. Add `run_id`, `source_file_id`, logical `source_row_number` (header = row 1), and load time. `ctl.source_file` stores filename/path, SHA-256 and row count. No scenario label, expected answer, generated status, or warehouse KPI is imported from a source. A file-level parse failure creates a failed run/file audit record and **no completed row dispositions**; bad business field values can land in Bronze and receive Q/AF later (SC shared conventions; malformed-file fixtures).

Normalization occurs in Silver working sets, with the original Bronze row retained. Allowed surrounding spaces on descriptive names are trimmed with AF; whitespace-only descriptive text becomes null/Unknown with AF. Keys/codes are **not guessed, case-folded, or silently fixed**. Exact duplicates compare every parsed field string under a binary collation, not just a hash. Equivalent duplicates compare every normalized field after only permitted normalization. A SHA-256 hash may narrow candidate comparisons but a field-by-field equality check decides DX/DE; distinct event IDs on the same physical attempt are not duplicate source rows (ER resolution order; F02).

For timestamps, accept only the exact 20-character `YYYY-MM-DDTHH:MM:SSZ` UTC whole-second grammar and a real Gregorian date; then use a tolerant conversion (`TRY_CONVERT` style 126 after validating/removing the final `Z`). Store as `datetime2(0)` with no timezone shift. Invalid text becomes null in a typed **working** value and receives the source-specific Q/AF decision; it remains verbatim in Bronze. For integers, first require ASCII digits and the documented range, then `TRY_CONVERT(int)`; boolean values are exactly `true`/`false`. Do not rely on SQL Server's permissive casts or convert an invalid value to zero. Use explicit binary/case-sensitive checks for IDs, codes, enums, and timestamp format (SC shared conventions; invalid-date variants). T/E are legitimate run settings, not CSV fields.

## Field-by-field mappings

Every row below also maps unchanged to the same-named raw Bronze field. `silver.*` names denote **selected accepted** rows; Q and duplicate rows remain in Bronze plus `silver.row_resolution` and `ctl.quality_issue`. Null typed FK values caused by malformed text do not erase the raw value. A valid-pattern FK with no parent stays in Silver and maps to an Unknown Gold member where allowed.

## Deterministic execution order and dispositions

1. **Preflight file boundaries.** Require exactly the six named files, read each with a standards-compliant CSV parser, verify UTF-8/headers/field counts/quoting, calculate SHA-256 and logical row numbers. Fail the refresh on structural defects; no row equation is asserted for an unparseable file (SC shared conventions; five malformed-file fixtures).
2. **Land raw text.** Insert each parsed row and provenance into the appropriate Bronze table. No casts or filtering here. Verify Bronze count equals the parser's count for every file.
3. **Classify exact and equivalent copies.** Mark extra identical parsed rows DX (lowest logical row number retains provenance); after permitted normalization, mark normalized-equivalent copies DE. Distinct message IDs describing one attempt remain separate accepted messages (ER resolution; F02, `exact_event_copy`).
4. **Resolve versions and immutable event IDs.** Validate business keys and ordering metadata; Q unorderable key groups, equal-version conflicting payloads, forbidden immutable changes, and differing payloads under one event ID. For a coherent versioned key select maximum source-issued version; lower versions DS. Do **not** fall back when the selected candidate's content later fails; `invalid_newest_booking` is Q newest/DS older. Recording/file order is never a business tie breaker (ER resolution; version/conflict variants).
5. **Resolve current masters and sites as of E.** Select accepted customers, depots, services, locations; validate location owner. Form exactly one `silver.customer_primary_location` per accepted customer, selecting only one active primary with no hold. Missing/conflicting/possibly quarantined primary candidates give Unknown geography, never a multiplied customer row. After detecting multiple active primary sites, mark each participating accepted current `customer_locations` source row AF and attach its own integration issue; keep prior attribute reasons and duplicate/version/quarantine dispositions. The customer-level enrichment issue does not change the `customers` source-row disposition (SC §4; ER primary selection; primary-location variants).
6. **Resolve shipment content and relationships.** Parse selected booking/milestones/certificate fields; required booking/key/commit defects Q, optional/dependent value defects AF. Keep valid-pattern unresolved customer/service/depot references AF for Unknown mapping. Classify cancellation and handover in the ER precedence; do not infer handover or promise (F11–F13; missing-reference and lifecycle variants).
7. **Resolve immutable events after shipments.** Q malformed ID/type/time/attempt metadata, impossible/pre-handover chronology, and unresolved parent (including parent Q); retain parseable identifiable-parent holds in `silver.event_hold`. Keep well-formed conflicting terminal/attempt claims accepted for Step 6C to flag after cross-event comparison. With missing handover, retain otherwise valid events with context flag, but no H-based coverage. Keep occurrence >T accepted and outside current reporting. After event resolution, an attempted shipment without a COMPLETE certificate and a missing-handover shipment with tracking receive integration AF. Step 6B AC/AF can still change at Step 6C for attempt, terminal, and certificate conflicts (ER C–D; F09/F14; demo defects).
8. **Collapse physical attempts.** Group accepted attempt messages by `(shipment_id,physical_attempt_id)`; matching sequence/time/result yields one coherent `silver.physical_attempt`. Different event IDs are not DX. Detect result/time/sequence disagreement, global attempt-ID reuse, duplicate sequences, sequence gaps, tied distinct attempt times, and attempts after a terminal. Preserve conflicts; never choose latest arrival or highest ID (ER A; F02/F07, attempt variants).
9. **Validate the complete source certificate.** For each shipment, check status/detail, booking ≤W≤attestation≤commit≤E, W≥T, C versus **all** coherent distinct attempts through W, sequences exactly 1…C, strictly increasing times, at/after handover, and at least one message per attempt recorded by attestation. Any applicable hold/conflict makes it unusable. First-attempt denominator additionally requires H, no T lifecycle conflict, and at least one attempt by T. A complete C=0 is valid but contributes no denominator (ER B; F08/F14; wider variants).
10. **Derive one shipment summary at T.** Use all supplied events recorded by E but only occurrences ≤T for T outcomes/coverage/attempt count. Quarantined terminal evidence creates Unknown rather than falsely open. Genuine incompatible terminals are Unknown; repeated same-kind confirmations use earliest occurrence. A later independent event cannot become a past outcome. Derive mutually exclusive reporting partitions and primary exclusion codes in ER order. Build generated dates, then expose current-run Gold views (ER cutoff/reconciliation; F01/F09/F10 and wider variants).
11. **Reconcile and publish.** Finalize exactly one `silver.row_resolution` disposition per parseable raw row and all `ctl.quality_issue` reasons. Prove source-row and H/D/attempt/coverage equations, Gold one-row grain and Unknown joins, record `ctl.run_check`, then atomically change the published-run pointer. A failed check leaves the previous publication active (ER reconciliation; PS acceptance).

`AC+AF` are current accepted source representatives; `DX+DE+DS` are duplicate/version dispositions; `Q` is quarantine. Flags/reasons can overlap but these six dispositions cannot. `R=AC+AF+DX+DE+DS+Q` is checked **per file**. A valid post-T booking/event remains AC/AF and is separately outside reporting, never reclassified Q. The accepted event split is by-T usable + by-T without valid handover + after-T. Source-row status and analytical eligibility are separate axes (ER row accounting; `booking_after_cutoff`, `success_after_cutoff`).
