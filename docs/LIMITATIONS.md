# Supported scope and limitations

**SYNTHETIC — FOR LEARNING ONLY.** This project demonstrates a local SQL Server warehouse for fictional Lumenland parcel operations. The business rules are those in [PROJECT_SPEC.md](PROJECT_SPEC.md), [SOURCE_CONTRACTS.md](SOURCE_CONTRACTS.md), and [EVENT_AND_CUTOFF_RULES.md](EVENT_AND_CUTOFF_RULES.md); this page records the practical boundary of the *implemented and tested* version.

## Reproducibility and environment

- The fixture, clean, and demo datasets completed **fresh** Bronze → reference Silver → shipment/event Silver → analytical Silver chains with the final code on a local SQL Server Express host. Gold and analysis were verified there. The [validation summary](VALIDATION.md) records a later repeat in a separate project copy, fresh Python environment, and **new explicitly selected database** on the same computer. A different-machine installation, different SQL Server edition/version, and cross-host timing remain unverified. This ZIP contains no active database publication.
- The local client uses ODBC Driver 18 and Windows integrated authentication. All SQL entry points now accept the same `--config PATH` with a validated database identifier; the historical `ParcelDeliveryWarehouse` name is still the omitted-option default when its local config file exists. The isolated Step 11 replay used a separate database and a deliberate certificate-trust exception for this local self-signed instance. These choices are narrower than a deployable authentication or certificate strategy; secret-based remote authentication is not supported.
- The generator-oracle discrepancy was resolved before this public edition. The [validation summary](VALIDATION.md) records that isolated regeneration matched all 18 approved fixture/clean/demo business CSVs and all four expected manifests, and the focused regression and full data validator passed. Regenerate the omitted edge-case corpus in a temporary project copy as shown in [SETUP_AND_RUN.md](SETUP_AND_RUN.md); the generator's default output is its project root. Operational transformations never consume expected-result manifests.
- Stage retries and publication rollback were tested for controlled failures. A hard process crash leaving a committed `RUNNING` audit marker without the normal failure handler is an operator-inspection path, not a demonstrated automatic recovery path. Historical one-time repair/correction scripts are not ordinary setup or replay commands.

## Reporting meaning and precision

- Reporting is a **single restated occurrence-time snapshot** at `2026-06-28T23:59:59Z`, using source evidence available by `2026-07-07T23:59:59Z`. It does not show what operators knew at the cutoff, reconstruct day-by-day backlog, or preserve SCD2 history. Current customer, depot, and service attributes are selected at export time. New evidence in a future export could restate the past answer.
- The [weekly promise-cohort query](../sql/analytics/03_weekly_service_performance.sql) groups shipments by their UTC promise week but evaluates all outcomes at that **one** reporting cutoff. It is not a series of historical weekly snapshots. A backlog aging band is also a single-cutoff view.
- Silver stores transit and overdue durations as exact integer seconds. Gold publishes `decimal(19,6)` hours **per shipment**; summing published hours can differ slightly from exact seconds divided by 3,600. Step 7 compared exact seconds; Step 8 analysis uses the approved six-decimal Gold values. Rates are 0–1 fractions in SQL and `NULL` for zero denominators.
- The active demo includes `UNK_CUSTOMER` facts but no fact assigned `UNK_SERVICE` or `UNK_DEPOT`. Step 7 verified those two missing-reference mappings with isolated published variants. An entirely empty published fact run was not created for Step 8; empty-population SQL behavior was checked through read-only variants. These limits should accompany any claim about what the active demonstration itself displays.
- [Query 10](../sql/analytics/10_first_attempt_performance.sql) outputs both an `is_total=1` all-handed-over row and `is_total=0` category rows. They are different presentation levels of the same shipments; summing both double counts. Use the flag when importing or charting the result.
- The warehouse reports confirmed outcomes from valid evidence. “Not confirmed on time” is not proof of a physically late delivery, and a complete attempt certificate is a source assertion simulated for this synthetic project, not an independently authenticated real-carrier ledger.

## Deliberate product boundaries

Version one has exactly six business CSV sources, full-refresh loading, one shipment-level Gold fact, four Gold dimensions, and 12 read-only SQL analyses. It has no pricing or financial analysis, real customers, dashboards, cloud deployment, incremental loading, SCD2 attributes, historical daily snapshots, route-causality model, or multi-parcel consignments. It is not positioned as a production service. The [business analysis](BUSINESS_ANALYSIS.md) presents synthetic descriptive findings, not causes or real-world benchmarks.
